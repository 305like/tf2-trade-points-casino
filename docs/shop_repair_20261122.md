# 상점 복구 및 거래 장부 수정 — 2026-11-22

## 복구 완료

- HTTP 503 원인: PHP가 접근해야 하는 비공개 `users` 저장소의 소유권이 PHP 사용자에서 호스팅 사용자로 변경된 상태. 폴더 0700/파일 0600 자체는 유지해야 하는 보안 설정이다.
- 기존 41개 파일을 외부 비공개 위치에 백업하고, PHP 사용자 소유의 새 저장소를 만든 뒤 파일별 SHA-256 일치 확인 후 전환했다. 기존 원격 폴더도 복구용으로 보존했다.
- 거래 URL 3개의 소유자 검증, 격리 데이터의 저장/재저장/계정 간 접근 거부 검증 통과. 임시 인증 복구 엔드포인트는 제거하고 HTTP 404 확인.
- 웹 상점 주요 탭 HTTP 200, 구매 페이지 판매 상품 4개 표시.
- 실제 봇의 입고·구매·반환·자금 처리 heartbeat 준비 상태 정상 확인.
- 상품 장부 6건, 정산 완료 주문 1건, 실패 주문 2건, 반환 완료 1건을 보존했다. 새 실제 거래는 보내지 않았다.

## 코드 수정

1. `shop-checkout.js`: 웹에 전송한 지급 거래번호 등 완료 부가 정보를 봇의 영구 장부에도 저장한다. 과거에는 웹에만 `payout_trade`가 남았다.
2. 기존 `settled` 주문에서 로컬 지급 거래번호만 없는 경우, 웹/봇 신원·가격·구매 영수증을 대조하고 Steam에서 해당 제안을 조회한다. 완료 상태·지급 대상·아이템·거래번호가 일치해야만 누락 필드를 보완한다. 새로운 제안 생성/전송이나 웹 거래 상태 변경은 하지 않는다.
3. `ledger-audit.js`: 양쪽이 정산 완료인 거래의 네 영수증 필드가 모두 존재하고 일치하는지 검사한다. 누락 필드를 조용히 통과시키지 않는다.
4. 예전 정책과 자금 모듈 mock이 누락된 테스트 두 개를 현재 코드에 맞게 수정했다. 아이템→게임 포인트 비활성화 정책은 그대로다.

## 검증

- Node 모의 테스트 13개 통과: 입고, 구매, 지급, 반환, 소유자 승인, 원장 검사/백업, 재시작/중복 방지 등.
- PHP 단위 테스트 7개 통과: 상품, 구매, 자금, 입고, 반환, 가격, 인증/배낭 파싱.
- 격리 Docker 웹 회귀 테스트 통과: 게임 세션, 상품 등록/표시, 구매 예약, 자금 부족, 구매자/판매자 권한, 판매대금 수령, 완료 이력, 반환.
- 신규 회귀 검사: 지급 거래번호 영구 저장, 과거 누락 복구 1회, 재실행 무변경, Steam 거래번호 불일치/보류 상태 복구 거부, 복구 과정의 거래제안 전송 0회.

## 적용 상태 / 남은 검수

수정된 봇 모듈 3개는 백업 후 업로드하고 파일 일치를 확인했다. 사용자가 호스팅 패널의 Node.js 거래 봇 재시작을 완료한 뒤 재검증했다.

재시작 후 확인 결과:

- 입고·구매·반환·자금 처리 준비 상태 모두 정상, Steam 폴링 기록 갱신 확인.
- 과거 정산 완료 1건의 누락된 지급 거래번호 보완 완료. 웹/봇 주문 신원·가격·상태·구매/지급 영수증이 모두 일치한다.
- 웹/봇 주문 집합 일치, 게시 상품 보관 소유권/자산 일치.
- 상품 6건, 정산 완료 1건·실패 주문 2건을 유지. 공개 판매 상품은 4개, HTTP 200.

실제 사용자 아이템을 새로 보내는 end-to-end 시험은 별도 승인된 계정/아이템으로 진행해야 한다. 이 검증 과정에서는 새 거래제안을 보내지 않았다.

호스팅이 소유권을 되돌린 원인은 아직 확인되지 않았다. private 폴더의 재귀 chmod/chown을 피하고, 호스팅의 소유권 재설정 작업을 조사해야 한다. 재발 시 빈 장부 생성, 원장 삭제, 0777/세계 읽기 허용으로 우회하지 않는다.

## 운영상 남은 우려 — 도박 제외

- 저장소 소유권 변경의 원인이 해결된 것은 아니므로 같은 접근 장애가 재발할 수 있다.
- 수정 후 새 실제 Steam 거래 전체 흐름은 미시험이다. 운영 장부 대조와 격리 테스트 통과를 새 실거래 완료 검증으로 표현하지 않는다.
- Steam 보류·요청 제한·통신 단절이나 전송 결과 불명확 상황에서는 중복 지급 방지를 위해 처리가 대기할 수 있다. 장기 대기 알림과 운영자의 검토/복구 절차는 추가 보강 대상이다.
- 이번 복구용 외부 백업은 확보했지만, 정기 외부 백업 및 호스트 유실을 가정한 복구 훈련까지 검증한 것은 아니다.
- 새 호스트로 이관할 경우 PHP/Node 권한, 고정 의존성, 봇 신원과 비공개 설정을 별도로 준비해야 한다. 공개 소스만으로 무설정 설치가 되는 제품은 아니다.

후속 정책: 아이템 충전 활성화는 사용자가 취소했다. 관련 런타임 코드와 운영 정책은 변경하지 않았으며, 충전/환전 비활성화를 유지한다.
